# kobook

[![CI](https://github.com/Rio-Oir/kobook/actions/workflows/ci.yml/badge.svg)](https://github.com/Rio-Oir/kobook/actions/workflows/ci.yml)

A local-first Chinese reader. Import an article from a link, a file or a paste;
read it with the layout and theme you like; select any passage to get an
explanation or ask a follow-up question; keep highlights and notes; back
everything up to a file; and keep reading when the network is gone.

Signed-in accounts add cloud sync across devices, and URL extraction can use
the bundled service. Model calls use *your* key, which the browser sends
directly to the endpoint you configure — never through this project's server.

## Quickstart

Node **24.12.0**, npm **11.6.2** (see `.node-version` and `package.json`).

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run dev          # http://127.0.0.1:5173
```

That is enough to import files or pasted text, read, and keep notes. URL
extraction, accounts and cloud sync need the optional service below; without
it the app keeps working locally.

### Optional service

Docker Desktop plus the bundled Caddy tool (verified on Windows x64):

```bash
npm run prisma:generate
npm run caddy:setup      # downloads and verifies the Caddy binary
npm run db:up            # PostgreSQL 17 on 127.0.0.1:55434
npm run db:migrate
npm run dev:all          # http://127.0.0.1:8080, Caddy proxies the SPA and /api
```

Development and tests need no real credentials: mail and SMS default to
in-process outboxes, and codes are read from `/api/dev/mail` and `/api/dev/sms`.
A production deployment must configure real transports — the server refuses to
start without them.

## Verification

```bash
npm run typecheck        # frontend, server and tests (Prisma client generated by pretypecheck)
npm run test:unit        # unit tests
npm run browser:install  # Chromium for the browser suites
npm run acceptance:base  # production build + service checks + a real browser
npm run verify           # the full serial gate
```

The database-backed suites (`test:phase1|2|3`, `test:browser:auth|articles`) need
`npm run db:up` and `npm run caddy:setup` first; they create their own throwaway
databases. `npm run acceptance:base` writes its evidence to
`docs/evidence/base-reproducibility/` (gitignored).

## Build

```bash
npm run build          # frontend → dist/
npm run build:server   # server → server/dist/
npm run build:release  # deployable reader → apps/reader-release/dist (served under /reader/)
```

`apps/reader-release/server.ts` shows one deployment shape: the API and the
built shell served from a single process. Serving `apps/reader-release/dist`
from any static host under `/reader/` works too, with the API behind the same
origin.
